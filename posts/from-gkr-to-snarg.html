From GKR to SNARG：从交互式电路验证到简洁非交互论证

LEARNING NOTE · FROM GKR TO SNARG

GKR 已经能够让一个高效 Verifier 验证大型算术电路的执行，但它仍然是交互式协议，而且其轮数会随电路深度增长。要进一步得到面向一般 NP 关系的 Succinct Non-Interactive Argument（SNARG，简洁非交互论证），还需要解决三个问题：如何摆脱原电路深度、如何让 Verifier 检查自己并不知道的大型 witness 或计算轨迹，以及如何消除 Verifier 的随机交互。对应的三个关键组件分别是 circuit flattening、Polynomial Commitment 和 Fiat–Shamir。

这篇文章不再拆解单个组件，而是把已经学过的工具拼起来：Flattening 把深计算变成浅验证电路，Polynomial Commitment 让未知的大型输入可以被绑定并在随机点打开，GKR 把整张电路正确性压缩到一个 evaluation claim，Fiat–Shamir 再把随机交互变成 transcript-derived challenges。

前置知识

本文默认已经理解 Sumcheck、Multilinear Extension、GKR、Polynomial Commitment 以及 Fiat–Shamir 的基本接口。这里关注的是它们为什么能够组成一套完整的 succinct argument。

如果原计算很深，直接在原电路上执行 GKR 仍然会让交互轮数受到 影响。另一方面，GKR 最终还会要求 Verifier 检查 input layer 的某个随机点 evaluation；当这个 input 本身是一个巨大 witness 或完整计算轨迹时，Verifier 并不知道它，也就无法自己完成最后一步。

问题一 Depth

原电路可能很深，GKR 的交互轮数会随深度增长。

问题二 Unknown Input

Verifier 不知道大型 witness 或完整 wire assignment，无法直接计算其随机点 MLE evaluation。

问题三 Interaction

即使前两项解决，GKR 仍然需要 Verifier 多轮发送随机 challenge。

从 GKR 走向 SNARG，就是依次解决这三个问题。

这里为什么已经“面向 NP”了？

NP 的核心就是存在一个 polynomial-size witness ，使 polynomial-time verification circuit 接受。只要这类验证计算能被 succinctly verified，就能够把任意 NP statement 统一转化成这种证明接口。

六、第四步：Fiat–Shamir 把 Interactive Argument 变成 Non-Interactive

Verifier 收到 后，只需按照完全相同的 hash 规则重新计算每轮 challenge，再执行原有的 GKR checks 和 PCS opening verification。

Fiat–Shamir 不是“免费去交互”

交互被消除后，soundness 不再只依赖原 GKR 的信息论随机挑战，还需要对 Fiat–Shamir hash 的安全性作密码学假设。本文只沿用这一范式，不把它表述成对任意 public-coin protocol 都自动成立的通用定理。

七、最终得到的 SNARG 到底是什么？

SNARG 的全称是：

把前面的组件合起来后，Prover 可以把一个原本很长的 NP witness 及其验证过程，转换成一个简洁的 cryptographic proof object ：

Verifier 不再需要访问完整 witness，也不需要和 Prover 在线交互，只需要：

  • 读取公开 instance 和 proof ；
  • 根据 transcript 重新计算 Fiat–Shamir challenges；
  • 检查 GKR 的所有局部一致性条件；
  • 检查最终 polynomial evaluation opening；
  • 最终接受或拒绝。

这里称为 Argument 而不是无条件的 Proof，是因为最终 soundness 已经依赖密码学假设：至少包括 polynomial commitment 的 binding，以及 Fiat–Shamir 实例化所需的安全假设。

S Succinct

证明与 Verifier 工作显著小于直接发送或重新执行完整 witness computation。

N Non-Interactive

Prover 一次性给出 ，Verifier 不再在线发送随机 challenge。

ARG Argument

对作弊 Prover 的安全性依赖计算假设，而不是对无限计算能力 adversary 的无条件 soundness。

八、SNARG、SNARK 与 NIZK 不要混在一起

这几个缩写经常同时出现，但它们描述的是不同性质。

概念 核心要求 本文构造是否自动得到
SNARG Succinct + Non-Interactive + Argument 是，目标就是这一层
SNARK SNARG + Knowledge Soundness / Extractability 否，需要额外的知识可靠性论证
NIZK Non-Interactive + Zero-Knowledge 否，本文没有自动提供 witness privacy
zk-SNARK SNARK + Zero-Knowledge 更不是自动得到，需要额外 ZK 机制
最容易犯的错误

“Non-Interactive”只表示不需要在线交互；“Succinct”表示证明与验证开销小；“Zero-Knowledge”表示不泄露 witness；“Argument of Knowledge”表示接受一个证明意味着能够提取相应 witness。四者是不同维度，不能因为系统用了 Fiat–Shamir、GKR 或 Polynomial Commitment 就自动全部成立。

九、最终记忆框架

从 GKR 到 SNARG 的主线可以压缩成四次“接口转换”：

01

Flatten

把深计算 转成浅电路对完整计算轨迹的 consistency check。

02

Commit

把 Verifier 不知道的大型 witness/table 绑定成可随机点 opening 的 polynomial commitment。

03

Reduce

GKR 把整个电路正确性逐层归约为一个随机 evaluation claim。

04

De-interact

Fiat–Shamir 用 transcript hash 生成 challenges，把交互式 argument 转成非交互 proof object。

  • Flattening 解决 depth：原计算越深，不代表验证电路也必须同样深。
  • MLE 解决 algebraization：把 witness / wire table 变成可以在随机域点求值的低度 polynomial。
  • Polynomial Commitment 解决 hidden input：先绑定整个 polynomial，之后只在所需随机点 succinctly open。
  • GKR 解决 large computation：把整张 shallow circuit 的正确性压缩到一个随机 evaluation claim。
  • Fiat–Shamir 解决 interaction：把 public-coin challenges 改由 transcript hash 产生。
  • 得到的是 SNARG：当前主线没有自动得到 Zero-Knowledge，也没有自动得到 Knowledge Soundness。
一句话总结：从 GKR 到 SNARG 的关键不是再发明一个新的“大协议”，而是把接口对齐：flattening 把任意深计算转换成浅一致性验证，Polynomial Commitment 绑定 Verifier 不知道的大型输入，GKR 把整个验证压缩成一个随机点 evaluation，PCS 完成该点 opening，最后 Fiat–Shamir 用 transcript hash 消除 Verifier 的在线随机交互，于是得到简洁的非交互论证。
