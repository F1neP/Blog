GKR Protocol：从电路执行到逐层多项式验证

LEARNING NOTE · GKR

GKR Protocol（Goldwasser–Kalai–Rothblum Protocol）的核心目标，是让 Verifier 不必重新执行整个大规模电路，就能验证 Prover 声称的输出是否正确。它先把电路按层组织，再把每一层的 gate-value table 通过 Multilinear Extension（MLE，多线性扩展）变成低度多项式，最后利用 Sumcheck 将“这一层正确”逐层归约为“下一层正确”，直到到达 Verifier 已知的输入层。

GKR 的核心不是逐个检查 gate，而是把整层计算编码成一个低度多项式声明，再把输出层声明逐层压缩到输入层。

前置知识

二、为什么简单的逐层抽查不够？

最直接的想法是：Verifier 从输出 gate 开始，让 Prover 给出它两个 child gate 的值。如果输出是假的，那么至少一个 child value 必然有问题；Verifier 随机挑一个 child 继续向下检查，直到输入层。

GKR 的关键改变是：不在两个 child 中随机选一个，而是先把离散 gate values 变成低度多项式，然后在整个有限域中选择随机点。这样就可以利用低度多项式在随机点上难以“碰巧伪装一致”的性质。

下一步该解决什么？

随机域点检查只有在对象具有低度多项式结构时才真正有用。但电路执行首先产生的是大量离散 gate values。于是 GKR 接下来先做两件事：第一，把电路整理成逐层的 value table；第二，再把这些 table 转换成低度多项式。先处理第一件事。

02

把 layer 与 wiring 做 MLE

把每层 gate-value table 和电路 wiring indicator 转换为有限域上的低度多项式。

03
LAYER REDUCTION

从输出层一路归约到输入层

每一层都把一个关于 的随机点 claim 改写为低度多项式求和，调用 Sumcheck 后转化为下一层的 claim。

最终到达 input layer。由于输入由 Verifier 已知，最后的 MLE evaluation 可以由 Verifier 自己计算，因此整个证明链闭合。

对象含义

ziVerifier 在有限域中使用的随机 evaluation point。
MLETable → Polynomial

给离散 gate values 加上低度代数结构。

SUMCHECKHuge Sum → Random Point

把大规模低度多项式求和压缩到随机点检查。

GKROutput → Input

把输出层正确性逐层归约到 Verifier 已知的输入层。

  • 不要把 MLE 理解成“每个 gate 变成一个多项式”：MLE 编码的是整层 gate-value table。
  • 不要把 Ṽi(r) 理解成某个 gate value：随机域点一般没有对应 gate。
  • MLE 不是信息压缩：它提供的是 low-degree algebraic structure。
  • Wiring 也必须代数化：ADD/MULT predicates 把电路拓扑写成 0/1 indicator functions，再做 MLE。
  • GKR 不直接验证所有 gate：它维护每层少量随机点上的 MLE claims。
  • Sumcheck 只是归约引擎：真正让电路可被 Sumcheck 的，是前面的 arithmetization、MLE 与 wiring polynomial。
一句话总结：GKR 先把“整个分层电路的正确执行”转写成一系列低度多项式关系，再利用 Sumcheck 把第 i 层的随机点声明归约成第 i+1 层的随机点声明，最终把输出正确性压缩到 Verifier 可以亲自检查的输入层。
