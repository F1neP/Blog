Secure Hash Algorithm 1（SHA-1，安全散列算法 1）

CRYPTOGRAPHIC HASH · SHA-1

SHA-1（Secure Hash Algorithm 1，安全散列算法 1）把任意长度消息确定性地压缩为 160 位摘要；它适合学习迭代散列结构，但碰撞安全性已经被攻破，不应再用于新的数字签名、证书或内容完整性方案。

一、算法基本信息及特征

TYPECryptographic Hash Function（密码散列函数）
OUTPUT160 bit
BLOCK SIZE512 bit
STATE5 × 32-bit words
ROUNDS每个消息分组 80 轮
STATUS碰撞安全性已失效

散列函数不使用密钥，也不是加密：它的目标是把消息映射为固定长度指纹。理想性质包括 Preimage Resistance（原像抗性）、Second-Preimage Resistance（第二原像抗性）与 Collision Resistance（碰撞抗性）；SHA-1 明确失效的是碰撞抗性。

二、详细算法流程图

预处理追加 1、若干 0 与 64 位原始长度，使总长为 512 的倍数
→
消息分组每个 512 位分组拆成 W₀…W₁₅，共 16 个 32 位字
→
消息扩展由异或与左循环移位生成 W₁₆…W₇₉
→
80 轮压缩A、B、C、D、E 结合 fₜ、Kₜ、Wₜ 逐轮更新
→
链接与输出工作变量加回 H₀…H₄；处理完全部分组后拼接 160 位摘要

三、SHA-1 的具体步骤

01
PADDING

填充并写入消息长度

设原消息长度为 ℓ 位。先追加一个比特 1，再追加 k 个 0，使 ℓ+1+k≡448 (mod 512)，最后追加 ℓ 的 64 位大端编码。

02
MESSAGE SCHEDULE

扩展 80 个消息字

03
COMPRESSION

用四组函数完成 80 轮

随后令 E←D，D←C，C←ROTL³⁰(B)，B←A，A←T。t=0…19、20…39、40…59、60…79 使用不同的布尔函数与常数 Kₜ。

04
FEED-FORWARD

加回链接值并处理下一分组

每个分组结束后，把 A…E 分别模 2³² 加回 H₀…H₄。初值为 67452301、EFCDAB89、98BADCFE、10325476、C3D2E1F0。

五、安全边界与实际选择

  • 碰撞已可实际构造：不能再依赖 SHA-1 证明两个不同文件“必然不同”。
  • 散列不等于认证：公开的 SHA-1(M) 不能阻止攻击者修改 M 后重新计算摘要；需要密钥认证时应使用 HMAC。
  • 不要直接散列密码：口令存储应使用专门的 Password Hashing（口令散列）方案及盐值。
  • 新设计：优先选择 SHA-256、SHA-3 或适用标准要求的 SM3。
一句话总结：SHA-1 通过填充、消息扩展和每分组 80 轮压缩生成 160 位摘要，但其碰撞安全性已不足以支撑现代新系统。
