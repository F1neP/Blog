Interactive Zero-Knowledge Proofs

LEARNING NOTE · INTERACTIVE ZERO-KNOWLEDGE

Interactive Zero-Knowledge Proof（交互式零知识证明）让 Prover（证明者）通过随机挑战证明某个命题成立，同时使 Verifier（验证者）除了“命题为真”之外，无法获得关于秘密 witness（见证）的额外知识。

核心不是“Verifier 完全没有看到消息”，而是：它看到的一切，都可以在不知道 witness 的情况下被模拟出来。

必要背景

NP Relation（NP 关系）R(x,w)=1 表示 witness w 能验证公开命题 x；Interactive Proof（交互式证明）的 Completeness（完备性）保护真命题，Soundness（可靠性）排除假命题；Commitment Scheme（承诺方案）用 Hiding（隐藏性）隐藏内容、用 Binding（绑定性）防止事后修改。相关定义可参阅复杂性与交互证明及承诺方案。

二、Simulator 与 Rewinding（回退）：模拟的是谁的视图？

01
REAL EXECUTION

真实世界

Prover 持有 witness w，与 Verifier V* 进行真实交互。V* 最终获得完整 transcript（交互记录）和自己的内部随机状态。

02
SIMULATED EXECUTION

模拟世界

Simulator 不知道 w。它把 V* 作为内部程序运行，通过选择消息、猜测挑战，必要时 Rewinding（回退并重新执行）来生成一份视图。

03
INDISTINGUISHABILITY

比较两个世界

如果任何有效区分器都无法判断视图来自真实交互还是 Simulator，那么真实协议就没有额外泄露 witness。

Simulator 与谁交互？

Simulator 不与现实中的 Prover 或 Verifier 交互。安全证明中，它通常获得对 V* 的代码或黑盒访问权，在自己的模拟环境中运行 V*。Rewinding 也是证明中的控制能力，不是现实参与者可以撤回已经发生的网络消息。

面对可能根据 t 决定挑战的 V* 时，Simulator 可以先猜测目标挑战 b̂，按上式构造 (t,z)，再运行 V*。若 V* 返回的挑战正好等于 b̂，就输出该 transcript；否则回退到发送 t 之前并重新尝试。因为 b̂ 只有两个选择，匹配概率为 1/2，期望尝试次数为 2。

疑问：y 是模 N 的余数，是否就说明 y 是 N 的二次剩余？

回答：不一定。只有存在某个 x 使 x²≡y mod N 时，y 才是模 N 的二次剩余。在协议中，y 是公开 statement 的组成部分，x 才是秘密 witness；Prover 不仅声称 y 是二次剩余，还要证明自己知道一个满足该同余式的平方根 x。

Witness 是整张图的合法染色方案。为了不泄露它，Prover 每轮先随机置换三种颜色，再承诺每个顶点的新颜色：

01
COMMIT ALL VERTICES

隐藏整张染色图

Prover 随机选择颜色置换 π，并对每个顶点的 π(c(v)) 进行 Commitment。这里 Hiding（隐藏性）保证 Verifier 暂时看不到颜色，Binding（绑定性）防止 Prover 在挑战后改变颜色。

02
CHOOSE AN EDGE

Verifier 随机抽一条边

Verifier 在 E 中随机选择 e=(u,v)，要求 Prover 只打开 Cu 和 Cv。

03
OPEN AND CHECK

只检查两个端点

Verifier 检查两个承诺都能正确打开，并确认 π(c(u))≠π(c(v))。其余顶点颜色始终保持隐藏。

通俗例子：检查考场座位图

把顶点想成学生，边表示两名学生相邻，三种颜色表示三套不同试卷。老师不看整张安排表，每轮随机抽查一对相邻学生，只确认他们拿到不同试卷。安排者每轮还随机重命名“甲、乙、丙”三套试卷，所以老师无法把不同轮次看到的颜色拼成完整安排。

从直觉到形式化证明

面对任意 V* 时，Simulator 需要预测它将检查的边，只为该边准备可打开的两个不同颜色，并用 Commitment 的 Hiding 隐藏其余模拟内容；如果预测不符，则通过 Rewinding 重新尝试。Binding 则用于 Soundness，防止真实作弊者看到被抽中的边后改变顶点颜色。

五、历史与关系脉络

1985 / 1989 Goldwasser–Micali–Rackoff：Zero-Knowledge

在 Interactive Proof 框架中提出知识复杂度与 Zero-Knowledge 的系统定义，并用数论语言展示“不泄露额外知识”的可能性。

1986 / 1991 Goldreich–Micali–Wigderson：所有 NP 语言的零知识证明

在适当的密码学假设下，将零知识从特定数论问题推广到全部 NP；三染色成为理解一般构造的经典入口。

前两项说明“真命题能通过、假命题难通过”，Zero-Knowledge 进一步说明“验证过程不泄露 witness”。

六、最终记忆框架

  • Zero-Knowledge：Verifier 的真实视图可以由不知道 witness 的 Simulator 生成。
  • View：包含公共输入、Verifier 的内部随机数以及交互 transcript。
  • Rewinding：Simulator 在安全证明中回退并重复运行 V*，不是现实协议参与者的能力。
  • 二次剩余协议：y 是公开 statement，x 是平方根 witness；同一承诺的两个有效回答能够提取 x。
  • Special Soundness：无法回答两个不同挑战意味着单轮欺骗成功率至多为 1/2。
  • 三染色协议：Commitment 隐藏并绑定颜色，随机抽边提供 Soundness，颜色置换隐藏原始染色。
  • Simulator 的意义：若真实视图与模拟视图不可区分，真实交互就没有提供额外有效知识。
一句话总结：零知识证明的核心判据是，验证者看到的视图可以由不掌握 witness 的 Simulator（模拟器）生成。
