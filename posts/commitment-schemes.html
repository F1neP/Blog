Commitment Scheme：Hiding 与 Binding

LEARNING NOTE · COMMITMENT SCHEMES

Commitment Scheme（承诺方案）让发送者先把一个秘密“锁定”，以后再公开：Hiding（隐藏性）保证接收者在打开前看不见内容，Binding（绑定性）保证发送者在承诺后不能反悔。

一句话记忆：先承诺、后打开；Hiding 保证“看不见”，Binding 保证“改不了”。

本篇范围

本文从 Commit Phase（承诺阶段）与 Open Phase（打开阶段）开始定义承诺方案，再介绍 Hiding、Binding、安全强度，以及从单向函数构造承诺的两种思路。Hiding 与 Binding 也会用于后续的零知识协议。

一、Commitment Scheme 到底在做什么？

最直观的比喻是“上锁的透明保险箱”。发送者 Alice 把写有答案的纸条放进去并上锁，先把保险箱交给 Bob；Bob 暂时看不到答案。等需要公开时，Alice 再交出钥匙。这里同时需要两件事：Bob 不能提前看，Alice 不能中途换纸条。

SEALED-BID AUCTION密封投标

例如，Alice 先对报价 80 生成承诺值 c；所有参与者提交承诺后，再统一公开报价。Hiding 使其他人无法在截止前看到 Alice 的报价，Binding 则阻止 Alice 在看见竞争者报价后把 80 改成 81。

COMMIT PHASE先固定消息

Alice 用消息 m 和随机数 r 计算承诺值 c，并先发送 c。

WAITING PHASE隐藏但已绑定

Bob 只持有 c，不能得知 m；Alice 也不应再改变 m。

OPEN PHASE公开并验证

Alice 发送 m 与 Opening Information（打开信息），Bob 验证它们是否与 c 一致。

性质限制谁禁止的事情常见强度
Correctness诚实双方诚实生成的承诺却无法打开Perfect（完美）/ Overwhelming（压倒性概率）
Hiding恶意接收者打开前识别消息Computational（计算）/ Statistical（统计）/ Perfect（完美）
Binding恶意发送者同一承诺打开成两个消息Computational（计算）/ Statistical（统计）/ Perfect（完美）

Computational、Statistical 与 Perfect 描述安全强度。以 Hiding 为例：Computational Hiding 只要求概率多项式时间接收者无法区分；Statistical Hiding 要求两种承诺分布的统计距离可忽略，即使接收者计算能力无限也几乎分不清；Perfect Hiding 则要求两种分布完全相同。Binding 也有对应层级，只是攻击方换成了发送者。

Hiding 与 Binding 的分工

Hiding 是接收者看不到“里面是什么”；Binding 是发送者不能改变“里面是什么”。二者面向的攻击方恰好相反。

四、无公共参数，以及 Adaptive / Non-Adaptive 在说什么？

1. “无公共参数”不等于“什么都不需要”

模式参数从哪里来需要注意的信任
CRS ModelCRS（Common Reference String，公共参考串）在协议开始前由所有人共同持有。需要说明 CRS 如何生成，以及生成者是否可能保留陷门。
Fresh ChallengeFresh Challenge（新鲜挑战）由接收者在本次交互中现场采样 R 并发送。不需要可信第三方设置，但多了一轮交互，并要求 R 按协议随机产生。
Plain ModelPlain Model（朴素模型）没有额外可信设置。仍然依赖计算假设、随机性、认证信道或交互结构。
疑问：无可信设置是否只是因为使用了更强的密码学原语？

回答：只说对了一部分。方案仍然使用密码学原语实现承诺，但它通过接收者在协议中发送新鲜随机挑战，避免预先建立可信 CRS；相应代价是协议需要交互。

2. Adaptive Security（自适应安全）与 Non-Adaptive Security（非自适应安全）

这两个词本身不是某个算法，而是安全游戏中对攻击者能力的描述。必须先说明“它在适应性地选择什么”：目标消息、被腐化参与方、查询或待攻击承诺。

NON-ADAPTIVE先选目标

攻击者在看到协议随机数、承诺或交互记录之前，就固定攻击对象与选择。

ADAPTIVE边看边选

攻击者可根据已经看到的参数与消息，再决定下一步攻击谁、查询什么。

SECURITY IMPACT适应性通常更强

若方案在合理的 Adaptive 模型下仍安全，它覆盖的现实攻击行为通常更广。

通俗地说，Non-Adaptive 攻击者像是在检查开始前就圈定一个保险箱；Adaptive 攻击者可以先观察一批保险箱及其标签，再挑最有利的一个下手。因此看到“自适应安全”时，第一问应当是：攻击者究竟被允许根据哪些信息改变哪项选择？

五、承诺方案为什么会出现在三染色证明里？

在 Graph 3-Coloring Zero-Knowledge Protocol（三染色零知识协议）中，Prover 先随机置换三种颜色，再对每个顶点颜色分别承诺：

H
HIDING

Verifier 看不到整张着色

验证者只要求打开随机选中边的两个端点。其他顶点的颜色仍由 Hiding 保护，因此不会泄露完整 witness。

B
BINDING

Prover 不能见题改色

所有顶点颜色必须在 Verifier 选择边之前承诺。Binding 阻止 Prover 在看到被抽查的边后，临时修改两个端点的颜色。

这说明承诺方案不是“加密的另一个名字”：它关心的是先固定、后公开的时间顺序，以及隐藏性与不可反悔性之间的组合。

六、最终记忆框架

  • Commit / Open：先发送 c 固定消息，之后发送 m 与 d 验证打开。
  • Correctness：诚实生成的承诺应当能够诚实打开。
  • Hiding：打开之前，恶意接收者不能有效识别被承诺的消息。
  • Binding：恶意发送者不能把同一个 c 有效打开成两个不同消息。
  • OWF → PRG → Commitment：单向函数可用于构造 PRG，PRG 再用于构造承诺。
  • 无可信设置：可能通过新鲜交互随机数实现，但并不表示没有假设、随机性或交互。
  • Adaptive：攻击者可以根据已经看到的信息再选择目标；必须明确它适应性选择的对象。
