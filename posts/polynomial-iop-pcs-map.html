Polynomial IOP 与 PCS：把 Oracle 查询编译为可验证承诺

PROOF SYSTEMS · IOP AND COMMITMENTS

现代 SNARK/STARK 通常先把计算变成多项式约束，再设计一个允许 verifier 随机查询少量位置的 IOP，最后用 polynomial commitment 或 Merkle commitment 把“理想 oracle”编译成真实消息。IOP 负责代数可靠性，承诺层负责绑定和查询认证。

一、三个证明模型的差异

模型Prover 提供Verifier 能做什么
PCP一次写定的长证明 oracle使用随机性查询少量位置
IOP多轮发送 oracle每轮在看到前序 oracle 后采样随机挑战和查询
Polynomial IOPoracle 被解释为低度多项式检查多项式身份、低度性与随机点求值

Sumcheck 和 GKR 可被看作 polynomial interactive proof/IOP 组件；PLONK 以单变量 polynomial IOP 组织置换与商多项式；STARK 使用编码后的 trace polynomial、低度测试和 Merkle 查询。

形式化定义与接口

多项式承诺方案至少包含 Setup,Commit,Open,Verify\mathsf{Setup},\mathsf{Commit},\mathsf{Open},\mathsf{Verify}Setup,Commit,Open,Verify。对次数受限多项式 fff，承诺 C←Commit(pp,f;r)C\leftarrow\mathsf{Commit}(pp,f;r)C←Commit(pp,f;r)；在点 zzz 的开证明 πz←Open(pp,f,r,z)\pi_z\leftarrow\mathsf{Open}(pp,f,r,z)πz​←Open(pp,f,r,z) 应满足：

Verify(pp,C,z,v,πz)=1iffv=f(z),\mathsf{Verify}(pp,C,z,v,\pi_z)=1\quad\text{iff}\quad v=f(z),Verify(pp,C,z,v,πz​)=1iffv=f(z),

并需要 binding/evaluation binding 保证同一承诺不能在同一点打开为两个不同值。一个 Polynomial IOP 只有在所有 oracle、查询点、批开策略和挑战顺序都被具体 PCS 正确编译后，才成为可部署 argument。

二、PCS 的四个基本算法

核心性质至少包括 commitment binding 与 evaluation binding：固定承诺后，攻击者不能对同一点成功打开两个不同值。Hiding 不是所有 PCS 默认提供的性质；例如基础 KZG 是确定性的，需要额外 blinding 才隐藏多项式。

接口不可省略的上下文

承诺必须绑定域、次数界、basis、变量顺序、协议与会话。只验证 而不绑定“f 代表哪个 witness polynomial”，上层 soundness 仍可能失败。

三、单变量与多线性多项式不是同一接口

UNIVARIATE，次数至多 d

KZG、IPA 和 FRI 常以单变量编码为中心；批量打开依赖线性组合或专门 multipoint 协议。

MULTILINEAR

MLE 对每个变量次数至多 1，但总表大小为 ；GKR/Sumcheck 自然产生随机多线性点。

把 MLE flatten 成单变量多项式会改变查询结构与次数；采用 multilinear PCS 则需要明确它的 commitment/opening 安全定义。二者不能仅因为都叫“polynomial commitment”就直接替换。

六、三类常见组合错误

  • 次数界没有被强制：随机点身份检查的可靠性依赖低度；允许高次多项式会放大伪造空间。
  • PCS 只绑定求值、不提供所需知识性质：上层 extractor 不能凭空从一个 acceptance equation 得到 witness polynomial。
  • 批处理挑战过早可见：prover 可自适应构造误差多项式，让组合检查为零。
一句话总结：Polynomial IOP 描述 verifier 应查询哪些低度对象以及为何少量查询足够；PCS/Merkle 层负责把这些 oracle 绑定并认证。一个完整证明系统必须逐项核对两层接口和安全性质。

七、选择 PCS 与编译 IOP 的判断框架

HIDING

隐藏性

并非所有 PCS 默认隐藏多项式；需要盲化版本时必须单独说明。

BINDING

求值绑定

同一承诺在同一点不能被打开为两个值，是编译可靠性的核心。

DEGREE

次数约束

验证求值正确不等于验证次数上界；部分方案需额外 degree bound 机制。

MODEL

模型匹配

单变量 PCS、MLE PCS 与 codeword low-degree test 的对象和接口不可混称。
