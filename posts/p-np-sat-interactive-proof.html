P、NP、SAT 与 Interactive Proof

LEARNING NOTE · COMPLEXITY & INTERACTIVE PROOFS

P（Polynomial Time，多项式时间）、NP（Nondeterministic Polynomial Time，非确定性多项式时间）与 SAT（Boolean Satisfiability Problem，布尔可满足性问题）区分了“能否快速求解”和“能否快速验证”；IP（Interactive Proof System，交互式证明系统）进一步允许 Verifier（验证者）使用随机挑战，通过多轮交互验证 Prover（证明者）。

先理解“一个答案为什么容易验证”，才能理解 Prover 与 Verifier 为什么需要交互，以及随机挑战如何约束作弊。

O(n)、O(n²)、O(n³) 都属于多项式时间；O(2ⁿ) 和 O(n!) 通常不属于。
为什么把它称为“高效”？

当输入长度增加时，nk 的增长通常比 2n、n! 温和得多，因此复杂性理论把多项式时间作为“可有效计算”的统一标准。不过这是渐近分类：次数 k 很大或常数 c 很大时，多项式时间算法在实际规模下仍可能很慢。

二、SAT 与 NP-complete：为什么一个问题能代表整个 NP？

SAT 询问：是否存在一组布尔变量赋值，使公式 φ 的值为真？

SAT EXAMPLE一个可以直接检查的 witness

取 witness (x1,x2,x3)=(1,0,1)，两个子句分别得到 1 和 1，所以 φ=1。寻找赋值可能需要尝试很多组合，但检查给定赋值只需逐个计算子句。

Cook–Levin Theorem（库克–列文定理）通过 Polynomial-Time Reduction（多项式时间归约）说明 SAT 是 NP-complete：

如果 SAT 存在多项式时间求解算法，那么所有 NP 问题都能先归约为 SAT 再快速求解，因此 P=NP。
疑问：尚未发现 NP 问题的快速算法，是否说明它无法被快速求解？

回答：不能这样断定。“尚未发现快速算法”不等于“已经证明不存在快速算法”。P 是否等于 NP 仍是开放问题；数学证明也不需要逐个穷举所有问题或所有算法，而可以通过归约、对角化或结构性定理一次覆盖无限多个对象。

三、Interactive Proof：随机挑战带来了什么？

IP 由计算能力不受多项式时间限制的 Prover P 和概率多项式时间的 Verifier V 组成。双方围绕公共输入 x 多轮交换消息。一般 IP 的诚实 Prover 是一个交互策略，并不要求存在一个多项式长度的 NP witness；只有在讨论 NP relation 或 Proof of Knowledge 时，才额外把秘密见证 w 纳入协议语义：

概率从哪里来？

概率主要来自 Verifier 的随机挑战。Prover 必须先固定前一条消息，再看到挑战；如果允许它看到挑战后重新选择承诺，Soundness 通常就会失效。

IP、NP relation 与 Proof of Knowledge 不要混用

IP 的 Completeness 与 Soundness 只讨论语言成员资格；NP relation 进一步写出 ；Proof of Knowledge 再要求从成功证明者中提取这样的 witness。后两者是证明系统的附加结构，不是一般 IP 定义自带的条件。

四、历史与关系脉络

1971 Cook–Levin：SAT 是 NP-complete

SAT 成为描述一般 NP witness 验证问题的标准起点：任意 NP 问题都可以在多项式时间内归约为 SAT。

1985 / 1989 Goldwasser–Micali–Rackoff：Interactive Proof

把概率验证者、多轮交互、Completeness 与 Soundness 纳入统一的证明系统框架，并进一步提出 Zero-Knowledge（零知识）。

1990 / 1992 Shamir：IP=PSPACE

说明交互与随机挑战显著扩展了高效 Verifier 能够验证的语言范围；IP 的表达能力达到 PSPACE（Polynomial Space，多项式空间），而不只是 P。

P 是否等于 NP 仍然未知；IP=PSPACE 则是已经证明的表达能力结论。

五、最终记忆框架

  • P：存在确定性多项式时间算法，可以快速求出判定结果。
  • NP：对于“是”实例，存在长度为多项式且可以被快速验证的 witness。
  • SAT：寻找使布尔公式为真的赋值，是第一个被证明为 NP-complete 的问题。
  • 多项式归约：若 L≤ₚSAT，就可以把 L 的实例高效转换成等价的 SAT 实例。
  • Completeness：真命题配合诚实 Prover 应当以高概率被接受。
  • Soundness：假命题面对任何作弊 Prover 都只能以很小概率被接受。
  • 随机挑战：必须在 Prover 固定前一条消息后产生，防止它只针对已知问题准备答案。
